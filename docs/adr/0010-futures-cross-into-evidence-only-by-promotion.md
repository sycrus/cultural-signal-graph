# Futures output enters forecast evidence only through promotion, which creates a new run

Futures mode is speculation and the forecast is an audit, so the boundary between them is one-way. Projections, wild cards, grounded assumptions and futures-scoped references share the run's RDF graph (a named graph per exploration, ADR-0007), but they never appear in the brief and never change the forecast's evidence. The one way across is **promotion**: a futures-scoped reference becomes a source of a **new** forecast run, with the same ask, the original sources plus the reference, and a record of which run, exploration and reference it came from. The original run and its explorations are untouched, and the exploration carries over to the new run. "Ground this" follows the same rule one step earlier: what it finds is only *proposed*, and the strategist accepts each item as a futures-scoped reference that records its stance (supports or contradicts). Nothing an agent finds enters even the exploration automatically, let alone the evidence.

This keeps a forecast reproducible back to its evidence: a brief can be traced to sources that were fixed when the run started, never to something speculation added later.

**Considered options:** promoting into the existing run (rejected: sources lock once a run starts, and changing them would invalidate the extraction, sign-off decisions and brief already made from them); keeping projections in a separate store with no link to evidence (rejected because projections must point at the evidence they grew from; ADR-0007); auto-adding Ground this results that clear a support threshold (rejected: an agent's judgment would become an anchor with no human in the loop, the same risk the sign-off gate exists to prevent); letting high-confidence projections feed the brief (rejected because projections carry no probability by design, so there is no defensible threshold).
